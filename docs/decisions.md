# 设计决策记录

## ADR-001：完整 Wiki 文章作为核心对象

小模型需要先判断主题是否已有，再决定写入。保留完整 Page 的正文、短摘要、来源和修订，PageCard 只承担选页索引；不把全文替换成记忆片段。现有实体表作为兼容存储，公共服务提供通用 Page 接口。代价是字段名称仍有历史实体语义。

## ADR-002：SQLite 是权威存储，Markdown 是投影

索引、引用、任务与版本必须保持一致。由服务写入数据库并生成 Markdown，避免模型随意覆盖文件。外部编辑需要先协调而非静默导入。这样更容易审计，但文件与数据库无法保证断电时完全原子。

## ADR-003：先保留可解释的词法基线

FTS5 的来源匹配能离线运行、复现和诊断，不引入向量服务部署与成本。Wiki 标题和正文使用关键词评分。代价是语义改写与中英文跨语言召回可能不足；后续用同一评测集比较词法、向量和混合检索，再决定是否增加 reranking。

## ADR-004：模型做计划，代码校验写入

模型先看卡片，再读已有全文与来源，产出有界计划。代码验证页面身份、来源、引用、版本和保留规则，转述增加独立证据判断。拒绝无法确认的输出比自动“修复”事实更可恢复；代价是更多审查任务和模型调用。

## ADR-005：冷却控制维护频率

稳定页面增加下次维护间隔，新证据重置相关工作。减少反复改写和模型消耗，不根据低访问率删除正文。任务队列持久化，但实际调用频率由宿主调度；当前库没有后台守护进程。

## ADR-006：来源变化与知识撤销分开

更新保留正文快照；撤回和替代保存事件并将相关页面置于审查。暂停默认问答，不擅自删除文章事实。代价是混合有效与失效来源的文章也暂时不可用于自动问答。用户或受授权维护调用修复证据后可恢复检索。

## ADR-007：online / offline 共用 shared 核心

模型调用是可选依赖路径，不另建一套离线数据库。两条路径复用来源、引用、修订、错误和配置约定，减少行为分叉。无密钥时提供可检索证据而非模拟生成答案。shared 指公共核心，不承诺多用户共享或同步能力。

## ADR-008：先验证文档解析，再考虑多模态

P1 已用 MarkItDown 转换文本 PDF/DOCX，必要时显式调用多模态 OCR。保留原始二进制、转换器版本和真实定位，避免转换文本里的页标记成为虚假引用。OCR 推测或图片描述不能直接当作逐字原文证据。详见 [P1 文档摄取方案](document-ingestion-plan.md)。
