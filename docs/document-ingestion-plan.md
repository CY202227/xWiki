# P1 文档摄取方案：MarkItDown 与多模态

状态：设计方案，尚未接入运行时。

采用两层解析：文本 PDF/DOCX 优先使用 MarkItDown；扫描页、嵌入图片或必要的版式区域，再按显式配置调用具备视觉能力的模型。维持可选依赖，Markdown/TXT 离线路径不需要这些服务。

[MarkItDown 官方文档](https://github.com/microsoft/markitdown)列出 PDF、Word 支持及按格式安装的 extras。[OCR 插件文档](https://github.com/microsoft/markitdown/blob/main/packages/markitdown-ocr/README.md)说明可使用视觉模型进行图片文字抽取。选择发布版本和安装范围时需要重新验证兼容性，不依据仓库 main 的功能直接承诺已发布包行为。

## 定位与证据契约

保留原始二进制、内容指纹、转换器版本和转换结果。PDF 必须保存真实页码；必要时逐页转换，不能把整份转换 Markdown 的人为分块编号称为物理页码。DOCX 使用段落、标题路径或表格单元定位，不能伪造物理页码。

当前引用模型是 `document_id + page_no + quote + content_hash`，因此先扩展定位类型和来源证据元数据，再接入 DOCX 或多模态。文本转换结果与视觉转录分别标记；视觉描述、推断、低置信度或不可读内容进入审查，不能按普通逐字原文直接免审。

## 有界调用与降级

只有转换结果为空、明显缺失或用户显式要求时才使用视觉模型，并限制文件大小、页数、像素、超时与调用数量。视觉模型仍优先选择不超过 30B 的实际部署；模型别名无法证明规模或视觉能力，必须验证并记录。现有测试模型尚未验证支持图片输入。

解析失败保留收件箱和原文，记录失败原因；不会把空文本当作成功，也不把整份文档默认发送给模型。缓存按原始内容、转换器和模型配置区分。

## 验收

使用原创文本 PDF、扫描 PDF、混合图文、带表格 DOCX、损坏与超大文件样本，检查文本保真、页/段落定位、数字与否定、跨页表格、模型调用预算以及重试。分别衡量解析失败、检索失败和生成失败。先完成摄取与引用，不把此方案视为已完成向量检索或所有知识视图。
