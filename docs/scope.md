# XWiki 2.0 范围

XWiki 是由小型语言模型辅助维护的小型知识库。完整 Wiki 文章是核心产品对象；PageCard、来源索引和关系是阅读与维护的入口。对话记忆不属于本项目职责。

目前 Python 包版本为 `0.2.0`；“2.0”指产品演进范围，不表示已经发布 `2.0.0`。

## 已实现的范围

- 摄取 Markdown/TXT；可选依赖支持文本 PDF、DOCX 正文段落与表格，归档原始文件并保留真实页或块定位。
- SQLite 保存文章、来源、引用、关系、修订、维护任务和来源历史；生成 Markdown 供阅读。
- 文档采用 FTS5 及词法回退；Wiki 文章采用可解释的关键词检索。当前没有向量检索。
- 检索原文证据，再由模型生成引用回答；无模型配置时只返回证据。
- 维护模型先读 PageCard，再选页、读全文和原文、制定有界操作计划。引用定位与逐字匹配由代码校验，转述由第二次模型调用审查。空操作是合法结果。
- 保存版本校验、修改理由、修订和回滚；来源变化标记受影响文章，失效证据不进入默认问答。
- 冷却调整维护频率，保持页面和来源；失败重试有上限，审查任务不能通过 force 绕过。

## 当前交付形态

可安装 Python 服务库及 JSON CLI。应用层可以接入现有后端、调度器或界面；仓库目前没有完整 Web 服务、生产网页、部署系统或常驻调度进程。

RAG 和 Wiki 已有基本流程，PageCard 与页面关系已实现。FAQ、Graph、Tree、PageIndex、MindMap、Timeline、Skills 可作为后续阅读视图或应用适配，当前不宣称已具备完整模式。DOCX 没有固定物理页码，后续索引不能伪造“原始页码”。

## 模型与预算

产品目标是使用最多 30B 的模型进行维护，按选页、来源和操作数量限制上下文。代码当前无法根据 API 的模型别名识别参数规模，也不自动强制 30B；部署者必须选择并记录实际模型。现有模拟与合成测试不能证明所有 30B 以下模型都能可靠运行。

模型可以决定是否保留待摄取来源、是否新建或更新文章，也可以选择不改写。自动维护不能删除、合并或重命名文章。来源撤回和替代由调用方明确操作；撤回保留历史，不等于物理删除。

## 验收与边界

公开示例可离线重放；CI 在 Windows/Linux、Python 3.10/3.14 验证测试、静态检查、80% 覆盖率门槛和安装构建。真实模型评测显式启用，使用单独数据集并说明样本规模及判分限制。

后续 OCR、多模态解析、向量与重排必须通过独立评测后接入。多用户鉴权、共享知识冲突、自动合并、隐私擦除和跨设备同步不在当前交付范围。
